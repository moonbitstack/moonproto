# moonproto

Protocol Buffers for MoonBit: the wire format, the descriptor model, binary, JSON
and text encodings, dynamic messages, the well-known types, a `.proto` parser,
and a `protoc` plugin that generates MoonBit message code.

## Status

The runtime, the encodings, the parser, the generator and the plugin are
implemented.

- `docs/design/inventory.md` — every capability the module covers, one row each,
  with where it lives.
- `docs/design/interface.md` — the types and signatures the implementation was
  written against, and the mechanism that replaces Go's runtime reflection and
  `unsafe` field access.

## Packages

| Package | Carries |
|:--|:--|
| `wire` | the wire format: tags, varints, fixed-width numbers, length-delimited values, groups, zig-zag, and the reader that reports where it stopped |
| `reflect` | `Value`, `Message`, `Enum`, `ListField`, `MapField`, the descriptor records, and the global registries |
| `desc` | building runtime descriptors from the descriptor shape, and converting back |
| `proto` | binary encode and decode, size, merge, clone, equal, reset, required checks, extension accessors |
| `json` | the JSON mapping: 64-bit integers as strings, enums by name, base64 bytes, maps as objects, and the `Timestamp`, `Duration`, wrapper, `FieldMask` and `Any` forms |
| `text` | the text format: one field per line, braces, comments |
| `delim` | varint size-delimited messages over a byte source |
| `dynamic` | messages, enums and extensions built at run time from descriptors |
| `known` | the well-known types, registered as dynamic types |
| `parser` | the `.proto` language: messages, maps, oneofs, groups, enums, services, reserved and extension ranges |
| `gen` | the plugin protocol and the MoonBit code generator: a request in, generated files out |
| `conformance` | the conformance protocol: read one format, write another, report the error |
| `cmd/protoc-gen-mbt` | the `protoc` plugin binary |

The root package is empty; a program imports the subpackages it uses.

## How it fits together

A message type is written by hand or generated by `cmd/protoc-gen-mbt`. It is an
ordinary MoonBit struct that implements `reflect.Message`, so the encoders, the
JSON mapping and the dynamic layer all reach its fields through the same trait.
The struct also has a companion `reflect.MessageType`, which the registries hold
so a type can be found by name — for example when decoding an `Any`.

Descriptors are plain records. `desc` builds them from the descriptor shape; the
encoders walk the descriptor and never look at a struct's layout. Cross-type
references are fully-qualified names resolved through a symbol table when the
file is built, which avoids the pointer cycles the reference implementation
solves with lazy pointers.

<!-- nocheck -->
```mbt
let msg = HelloRequest::new()
msg.set_name("moon")
let bytes = @proto.encode(msg)
let back = HelloRequest::new()
@proto.decode(bytes, back)
```

## Parsing and generating

`parser.parse(file_name, source)` returns the descriptor shape, which `desc`
turns into runtime descriptors. `gen.generate_source(file)` returns MoonBit
source for one file, and `gen.plugin_main` speaks the `protoc` protocol: a
serialized `CodeGeneratorRequest` in, a serialized `CodeGeneratorResponse` out.
`cmd/protoc-gen-mbt` wires that to standard input and output.

## Conformance

`conformance.handle` reads a `ConformanceRequest`, decodes the payload in the
format it carries (binary, JSON or text), and returns the requested output
format or the parse or serialize error. `conformance.register_test_types`
registers a message that exercises every scalar kind, a packed repeat, a map, a
nested message, an enum and a oneof.
