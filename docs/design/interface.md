# Interface draft: packages, types, signatures, and what replaces Go's reflection

This is the interface the implementation was written against. The tables are
the shape reference; where the code departs from them, the departure is
recorded under "Implementation notes" below. The judgment here is about shape:
which types, which methods, which parameters, and what each one costs.

The reference is the Go implementation of Protocol Buffers. Two of its
load-bearing mechanisms have no MoonBit counterpart, and the shape of this
interface is mostly a consequence of replacing them:

1. **Runtime reflection plus `unsafe` field offsets.** Go reads and writes a
   message's fields by an offset computed at program start from struct tags
   (`internal/impl`). MoonBit has no runtime type information and no struct
   tags.
2. **Interface values (`any`) as the universal carrier.** Go's `Value` union and
   the extension conversions are built on `any` and on `unsafe` packing.

Neither is replaced by an emulation of the missing mechanism. The replacement is
in the table below, and it is the single most important thing to review here.

## What replaces each Go mechanism

| Go mechanism | Where it appears | What carries it here |
|:--|:--|:--|
| `protoreflect.Message` interface: `Descriptor`, `Get`, `Set`, `Has`, `Clear`, `Mutable`, `NewField`, `Range`, `WhichOneof`, `GetUnknown`, `SetUnknown` | `reflect/protoreflect/value.go` | `pub(open) trait Message`, written by hand for a dynamic message and emitted by the generator for every generated message |
| Field access through `unsafe` offsets computed from `protobuf:"..."` struct tags | `internal/impl` (16k lines of coders) | **Deleted.** The generated `impl Message` matches on `FieldNumber` and reads or writes a named struct field. There are no offsets, no tags, and no coder table. The `reflect` package never learns a message's layout. |
| `protoreflect.MessageType`: `New`, `Zero`, `Descriptor` | `value.go` | `pub(open) trait MessageType`; the generator emits one zero-sized companion per message |
| `protoreflect.Enum` / `EnumType` | `value.go` | `pub(open) trait Enum` / `EnumType`; a generated enum is a MoonBit enum implementing `Enum` |
| `protoreflect.Value` union (`type value struct` + `unsafe` packing) | `value_union.go`, `value_unsafe.go` | `pub(all) enum Value` — a tagged enum. No `any`, no packing, no `unsafe`. |
| `protoreflect.MapKey` | `value_union.go` | `pub(all) enum MapKey`, a six-constructor subset of `Value` |
| `protoreflect.List` / `Map` | `value.go` | `pub(open) trait List` / `Map`; composite `Value` variants hold `&List` / `&Map` |
| `ProtoMessage` (`ProtoReflect() Message`) | `protoreflect/proto.go` | generated messages implement `Message` directly; `proto` takes `M : Message`, so there is no second wrapper interface |
| `protoiface.Methods` fast path | `runtime/protoiface` | `pub(open) trait Methods`; a generated message may implement `marshal` / `unmarshal` / `size` / `merge` to bypass the generic descriptor walk. Absence means the generic path is used. |
| `protoregistry.GlobalFiles` / `GlobalTypes` (mutable global maps) | `reflect/protoregistry` | `reflect.global_files` / `reflect.global_types`; generated files call a generated `register` function from the package's initialization |
| `internal/filedesc` lazy descriptor builders with `sync.Once` caches | `internal/filedesc` | `desc` builds every descriptor eagerly in one pass and returns immutable values; there is no lazy cache and no `once` |
| `descriptorpb.FileDescriptorProto` etc. as Go structs | `types/descriptorpb` | `known/descriptor`, `known/plugin`, `known/features`, generated by this module's own `cmd/protoc-gen-mbt` and checked in |
| `encoding/protowire` append-and-return-slice | `encoding/protowire` | `wire` appends into a `Buffer`; readers take a `BytesView` and an explicit `at`, and report where they stopped |
| `protogen`'s `GoIdent` / `GoImportPath` machinery | `compiler/protogen` | `gen`'s `MbtIdent` / `MbtImportPath`; the emission helpers are MoonBit-shaped (`p`, `qualified_ident`, `import`) |

The consequence worth stating plainly: **`internal/impl` does not port.** It is
the one package whose job is to defeat the language's type system, and here the
type system is on our side. Its 16k lines collapse into code the generator
writes per message. The `reflect` package is then small and total: it can walk
any message through `Message` and any descriptor through `Descriptor`, because
both are traits rather than struct layouts.

## Package layering

```
wire                      tags, varints, fixed widths, groups; no dependencies
  ↑
reflect                   descriptors, Value, Message, Enum, List, Map, registries
  ↑
known                     well-known types, descriptor/plugin/feature messages
  ↑
desc                      FileDescriptorProto ⇄ runtime descriptors
  ↑
proto                     binary encode/decode, merge, clone, equal, size, extensions
  ↑
json · text · delim       the other three encodings
dynamic                   messages built from a descriptor at run time
gen                       the plugin framework
  ↑
cmd/protoc-gen-mbt        the protoc plugin binary
```

`reflect` is the only package everything else sees. `desc` depends on `known`
because it converts `known/descriptor` messages; `known` is checked in, so the
bootstrap loop (`gen` → `desc` → `known` → generated by `gen`) is broken the same
way the reference breaks it: regenerate with the previous generation's binary.

## Conventions that apply to every package

**Names.** The organisation's words, not Go's: `parse`, `encode` / `decode`,
`of` (the wire value back to a value), `code` (the wire value out), `is_`
predicates, `kind` for "which one", `strict` for turning tolerated input into an
error. A record parameter is named after its type, lowercased, and has a preset
of the same name: `MarshalOptions` → `marshal_options~ : MarshalOptions =
marshal_options`. Method names on descriptors follow the reference where the
reference's name is already a noun (`fields`, `messages`, `by_name`); `Len` /
`Get` become `length` / `get`, as core does.

**Errors.** Every package that can refuse input defines one
`pub(all) suberror Refused`. Offsets are `at`, observed values `got`, expected
values `want`, upper bounds `limit`, a group of bounds `limits`. A `Refused`
raised by a lower package is carried as a payload, never stringified:
`proto.Refused::Wire(@wire.Refused)`. Reading an index out of range returns
`Option`; `at` aborts, as core's `op_get` does.

**Optional parameters.** Two shapes only: `x? : T` when there is no preset and
the callee branches on absence; `x~ : T = v` when there is a preset. Never
`x~ : T? = None`. Priority is library preset < record passed in < same-named
parameter on the call.

**Mutability.** A message is a struct with `mut` fields. MoonBit gives such a
struct reference semantics, so `decode` writes the destination in place, as the
reference does, and a composite `Value` obtained from `mutable` aliases the
message. A generated message has one representation; the reference's Open /
Opaque split is not reproduced.

**Traits and extension.** Every contract that a third party may implement is
`pub(open) trait`; the library's own types implement it. A generated `impl` in
the type's own package triggers the implicit-promotion warning, so the generator
emits `pub extend <Type> with <Trait>::{<method>}` beside the `impl`.

**Equality and hashing of descriptors.** Descriptors are trait objects. Two
descriptors are equal when they are the same object; two descriptors that
describe the same proto type may still be distinct, which is the reference's
semantics and is stated on `Descriptor` rather than papered over.

## `wire`

Field numbers, tags, and the five wire types; the byte reader that says where it
stopped and why. `FieldNumber` is `Int32` in the proto range; `WireType` and
`Type` are enums over the wire tags 0–5.

```mbt
pub type FieldNumber = Int32

pub(all) enum WireType {
  Varint
  Fixed64
  LengthDelimited
  StartGroup
  EndGroup
  Fixed32
}

pub fn WireType::code(Self) -> Int32
pub fn WireType::of(Int32) -> Self raise Refused

pub(all) enum Refused {
  Incomplete(at~ : Int)
  Malformed(at~ : Int, got~ : Int, want~ : Int)
  Overflow(at~ : Int)
  FieldNumber(at~ : Int, got~ : Int)
  WireType(at~ : Int, got~ : Int)
  Recursion(limit~ : Int)
  Size(got~ : Int, limit~ : Int)
}
```

| Function | Signature | Cost |
|:--|:--|:--|
| `append_tag` | `fn append_tag(Buffer, FieldNumber, WireType) -> Unit` | O(1) |
| `append_varint` | `fn append_varint(Buffer, UInt64) -> Unit` | O(1) |
| `append_fixed32` / `append_fixed64` | `fn append_fixed32(Buffer, UInt32) -> Unit` / same for 64 | O(1) |
| `append_bytes` / `append_string` | `fn append_bytes(Buffer, BytesView) -> Unit` / `fn append_string(Buffer, StringView) -> Unit` | O(n) |
| `append_group` | `fn append_group(Buffer, FieldNumber, BytesView) -> Unit` | O(n) |
| `consume_tag` | `fn consume_tag(BytesView, at~ : Int = 0) -> (FieldNumber, WireType, Int) raise Refused` | O(1) |
| `consume_varint` | `fn consume_varint(BytesView, at~ : Int = 0) -> (UInt64, Int) raise Refused` | O(1) |
| `consume_fixed32` / `consume_fixed64` | `-> (UInt32, Int)` / `-> (UInt64, Int) raise Refused` | O(1) |
| `consume_bytes` / `consume_string` | `-> (BytesView, Int)` / `-> (StringView, Int) raise Refused` | O(1) |
| `consume_group` | `fn consume_group(BytesView, FieldNumber, at~ : Int = 0, limits~ : Limits = limits) -> (BytesView, Int) raise Refused` | O(n) |
| `skip_field` | `fn skip_field(BytesView, at~ : Int = 0, limits~ : Limits = limits) -> Int raise Refused` | O(n) |
| `size_tag` / `size_varint` / `size_bytes` / `size_group` | `-> Int` | O(1) |
| `encode_zigzag` / `decode_zigzag` | `fn encode_zigzag(Int64) -> UInt64` / `-> Int64` | O(1) |
| `encode_bool` / `decode_bool` | `fn encode_bool(Bool) -> UInt64` / `-> Bool` | O(1) |
| `decode_tag` / `encode_tag` | `fn decode_tag(UInt64) -> (FieldNumber, WireType) raise Refused` / `-> UInt64` | O(1) |

```mbt
pub(all) struct Limits {
  depth : Int
  size : Int
}
pub let limits : Limits = { depth: 10000, size: 1 << 31 }
```

`Limits` is the recursion depth and the byte ceiling for a single message. The
defaults are the reference's: depth 10000, no practical size ceiling. A reader
takes `limits~` on every call that can recurse or allocate; the record is
preset, the per-call parameter overrides it.

`empty` has no Go counterpart: Go's `MessageType.New()` returns the interface
type, while a MoonBit generic `clone[M : Message](M) -> M` needs to name the
concrete type. `empty` is the one method that makes generic clone, decode and
merge return `M` rather than `&Message`. A dynamic message returns itself.

| `range_extensions` | `fn range_extensions[M : Message](M, (&ExtensionType, Value) -> Bool) -> Unit` | O(k) |

`decode` takes the destination by value and writes it in place: a message is a
struct with `mut` fields, so the caller's binding and the callee's `self` alias.
`merge` takes the source as `&Message` because it may be any implementation,
while the destination is `M` so that a generated message's own fields are
written directly.

## `cmd/protoc-gen-mbt`

The binary: read a `CodeGeneratorRequest` from standard input, write a
`CodeGeneratorResponse` to standard output, and accept the same parameters the
reference accepts (`paths=source_relative`, `module=`, `annotate_code`, and the
feature-level overrides). It is an executable package, run as
`moonx moonbitstack/moonproto/cmd/protoc-gen-mbt`.

## What this draft does not settle

- The exact generated-code shape: whether a generated message exposes named
  fields, accessors, or both. The interface only requires that it implements
  `Message`.
- The text of `Refused` variants beyond the four the organisation fixes
  (`at`, `got`, `want`, `limit`). Each package will add the variants its own
  failures need.
- Whether `wire`'s `Buffer` is core's `Buffer` or a thin wrapper that reserves a
  size prefix. That is an implementation choice; the signatures above do not
  depend on it.

## Implementation notes

The implementation settled several points the draft left open.

- **Descriptors are records, not traits.** `FileDescriptor`, `MessageDescriptor`
  and the rest are `pub(all) struct` values; collections are arrays on the
  record. Cross-type references are fully-qualified names, resolved through a
  symbol table in `desc`, which removes the pointer cycles the trait-object
  draft would have needed.
- **`List` and `Map` are `ListField` and `MapField`.** Core already owns those
  names, so the field views were renamed; `Value` carries `ListView` and
  `MapView`.
- **`Message` is object-safe; `Fresh` returns the concrete type.** A `Value`
  holds `&Message`, so no method on `Message` may return `Self`. The one
  constructor that does — for generic clone and decode — is `Fresh::fresh`.
- **`parser`, `gen` and `conformance` are additional packages.** The parser
  produces the descriptor shape directly; the generator speaks the `protoc`
  protocol and emits MoonBit source; the conformance harness reads one format
  and writes another.
- **Extensions are fields with a flag.** `Message` grew `range_extensions`, so
  the encoder writes an extension through the same path as a declared field,
  and the decoder resolves an unknown number against the extension registry
  before it decides the bytes are unknown. JSON keys an extension by its
  bracketed full name and the text format by its bracketed name.
- **`Struct`, `Value` and `ListValue` are JSON.** The encoders special-case the
  three full names: a `Struct` is an object, a `ListValue` an array, and a
  `Value` whichever JSON kind its oneof holds. `Any` prints expanded in the text
  format.
- **Editions are resolved while parsing.** `Features` carries the six edition
  features, `Features::merge` layers a child over its parent, and the builder
  turns the result into the booleans the runtime already had: presence,
  packing, `Group` for a delimited field, and `closed` on an enum.
- **Options are preserved, not interpreted.** A declaration's options are kept
  as (name, value) pairs on the file descriptor's `option_map`, reachable by
  `option_of(declaration, name)`; a feature option is applied rather than kept.
- **The well-known types are generated.** `known/google/protobuf` is the
  plugin's output for the `.proto` files protobuf 36.2 ships, checked in;
  `known` is a thin lookup over it. `descriptor.proto` alone is eleven thousand
  generated lines, so this is also the generator's real-schema test.
